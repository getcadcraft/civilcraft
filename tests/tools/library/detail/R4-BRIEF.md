# Round 4 brief: 150 objects per category for restaurants, airports and shopping centres (2026-11-03)

You are adding generic Library objects. The owner's ask: "150 items per category: things that have to do with restaurants, airports and shopping centres/malls/retail", very high fidelity. Each object is a published, CC0, "Generic" item with its own plan and 3D detail. Read `docs/LIBRARY-BLOCKS-GUIDE.md` (rules that do not bend) and `docs/LIBRARY-BLOCKS-REPORT-2026-11-03.md` (what round 3 did) first. Work in `/var/www/CADCRAFT/getcadcraft.com`.

## What you make

For each group you own, one file `tools/library/detail/r4-<group>.mjs` that `export default [ fam({...}), … ]` with **exactly 150 variants** in all. A *family* is one builder plus a list of real size or configuration variants; each variant is one object (`name = title + ", " + label`). Examples of honest variants: widths 24/30/36/48/60/72 in, 2/3/4/6 burners, 1/2/3 doors, single/double/triple deck, 4/6/8 seats, low/standard/tall. Do NOT make a variant that only renames the same object, and do not make 150 near-copies of three ideas: aim for at least 20 families per group, and every family should draw something real (doors, drawers, pulls, shelves, seats, burners, fans, panels, rails, glazing, wheels, hinges), not a box. Spread the families over the group's sub-categories (see `LibraryCatalog::CATEGORIES` in `public_html/core/classes/LibraryCatalog.php`) and over the three settings: **restaurants** (kitchens, dining, bars, food courts, drive-throughs), **airports** (check-in, security, gates, baggage, concourse, airside and landside, ground support), **shopping centres, malls and retail** (stores, fixtures, kiosks, cash wraps, fitting rooms, atriums, parking, storefronts). Roughly a third each, more where a group suits one setting.

## The API (read `com-core.mjs`, `fam.mjs`, `r4-kit.mjs`, and the round-3 files `com-*.mjs` for ready patterns to copy)

```js
import { fam, cab, tbl, pull, T, GAP, leaves, F, FU, M, S, C, O, A } from './r4-kit.mjs';
export default [
  fam({ cat: 'foodservice/cooking', title: 'Generic conveyor pizza oven',
        desc: (v) => `Conveyor oven with ${v.decks} decks, an open belt at each end and a control panel.`,   // ONLY what build() draws
        vs: [ // [label, width in, depth in, height in, z in (bottom above floor), params]
          ['single deck, 32 in belt', 62, 40, 66, 0, { decks: 1 }],
          ['double deck, 32 in belt', 62, 40, 70, 0, { decks: 2 }] ],
        build: (a, v) => { /* draw with a.* ; end with: */ a.log('Added the decks, belts and panel (plan and 3D).'); } }),
];
```
`a` is an `Acc` for the object's body box, **millimetres, z up, plan front at −Y, back at y = 0, x from −w/2 to +w/2**. Fields: `a.X0 a.X1 a.YF(front, negative) a.YB(=0) a.Z0 a.Z1 a.W a.D a.H a.cx a.cy`. 3D: `a.box(x0,y0,z0,x1,y1,z1)`, `a.cyl`, `a.cone`, `a.xcyl`, `a.ycyl`, `a.ell`, `a.tube`, `a.prism(poly,z0,z1)`, `a.frame`, `a.caster`, `a.leg`. Plan: `a.outline()`, `a.rect`, `a.circ`, `a.line`, `a.arc`, `a.ellp`, `a.poly`, with layers `'EQUIP'` (default outline), `'EQUIP-DETAIL'`, `'EQUIP-HIDDEN'` (dashed), `'EQUIP-SWING'` (door swings); `a.clear(name,x0,y0,x1,y1,h)` for a clearance zone. Every `build` must call `a.outline()` (or draw a plan outline), draw real 3D, draw plan detail, and call `a.log('Added …')` (the version note). `cab()` is the parametric cabinet (doors, swings, drawers, glass, louvers, toe kick, legs, casters, splash, open shelves, locks, panels) and `tbl()` the parametric table; the namespaces `F FU M S C O A` hold the helper functions of the round-3 files (stand, knobs, collar, louvers, flange, tank, pumpSet, post, vehicle, person, plate, signOnPost, lamp, grate, swingLeaf, cushion, star, dial, round, burners…). Copy patterns from those files freely; keep the geometry inside the body box (the checker warns when it leaves it). Keep a variant under about 6,000 triangles (people with `hi` figures are the heavy ones: pass `lo: true`).

## Rules that do not bend

- Every title starts with `Generic `. No maker, no model, no catalogue number, no brand, no airline, no store or restaurant chain, no named standard in a name. Aircraft are "narrow-body", "regional jet", "turboprop"; vehicles are by type. Sizes are generic.
- The description says only what the object really has and draws. No marketing. People are scale figures: say so when it matters.
- The library's privacy check refuses a name or description that reads like a person's or client's name: a capitalised word followed by `house`, `home`, `lot`, `project`, `property`, `cabin`, `villa`, `estate`, `ranch`, `job`, `addition`, `renovation`, `residence`, `remodel` ("parking lot", "coffee house" fail), a capitalised possessive ("Baker's rack"; lower-case "baker's" is fine), a number followed by up to three words and a street word (`way`, `drive`, `court`, `place`, `lane`, `road`, `circle`… e.g. "10 ft drive-through" fails: write "drive-thru"), phone-like digit groups. `make-round4.mjs --check` tests all of that.
- Names are unique across ALL block CSVs (`tools/library/blocks/*.csv`, about 1,300 existing names) and across the other agents' files. Put the size or configuration in the label so two variants never collide. Sizes in inches, `z` = bottom above the floor (96 for a ceiling light, 54 for a wall cabinet).
- `cat` must be a real key of `LibraryCatalog::CATEGORIES` that belongs to your group.
- Do not edit any shared file (`fam.mjs`, `make-round4.mjs`, `commercial.mjs`, `com-*.mjs`, `detail.mjs`, `front.mjs`, `r4-kit.mjs`, other agents' `r4-*.mjs`). Your files are only `tools/library/detail/r4-<your group>.mjs` (you may add helper functions inside them). Do NOT run `bin/library-seed.php`, touch the database, or publish anything: the lead publishes after review.

## Workflow (iterate; look at what you draw)

1. Write families in batches of 3–5, then check: `node tools/library/detail/make-round4.mjs --check --files r4-<group>.mjs` (the `--files` flag loads only your file, so another agent's half-written file cannot stop you; errors must reach zero; the "geometry leaves the body box" warnings should too, or be explained).
2. Look at them: `node tools/library/detail/r4-preview.mjs tools/library/detail/r4-<group>.mjs <scratch-dir> --all` writes front elevations and contact sheets `<scratch-dir>/sheet_NN.png` (30 per sheet, labelled). **Open the sheets with the Read tool** and fix what looks wrong: floating parts, blank boxes, a front wall hiding the interior, parts outside the body, objects that do not look like what the name says. Use a scratch dir under your session scratchpad (never `/tmp` directly, never inside the repo).
3. When the group reaches 150: `node tools/library/detail/make-round4.mjs --files r4-<group>.mjs --expect <group> --write --groups <group>` then `node tools/library/detail/detail.mjs --check` (all items must validate; it reads the CSV you just wrote). Fix anything it reports.
4. Final review of your whole group on contact sheets once more, then report.
