许多城市和县在项目结束时要求提供 GIS 格式的竣工数据：管道和构筑物的位置、最终场地标高、道路中线等。**GIS › 导出**会将 CivilCraft 中的内容按对象类别分别写入为 GIS 图层，每类对象一个图层。

## 导出前

1. 在{{ui:坐标}}中设置项目的坐标系。GIS 部门需要知道数字的位置；若没有坐标系，文件将保留项目自身的数值，且不会注明任何坐标系名称。
2. 按希望交付的方式检查曲面、路线、平台和管网。
3. 向部门确认所需的格式和坐标系。许多部门仍要求使用州平面坐标带中的 shapefile；较新的系统则采用 GeoPackage。

## 导出

1. 单击**GIS**组中的{{ui:导出}}。
2. 在**内容**下勾选要发送的类别。每个类别后显示其要素数量；尚无要素的类别呈灰色不可选。
3. 在**格式**下选择文件格式。
4. 阅读关于坐标和单位的说明，然后单击下载按钮。状态行会说明已写入的内容，以及被缩短的字段名。

该对话框还包含高程格网导出（{{ui:曲面导出为GeoTIFF高程格网}}），参见[高程格网和 LiDAR](topic:elevation-grids-and-lidar)。

## 各类别包含的内容

| 类别 | 图形 | 字段 |
|---|---|---|
| 测量点 | 带高程的点 | `P` 点号、`N` 北坐标、`E` 东坐标、`Z` 高程、`D` 描述 |
| 原地面和设计曲面的等高线 | 带高程的线 | `ELEV` |
| 断裂线 | 带高程的线 | `NAME` |
| 曲面边界 | 面（已绘制的边界，否则为曲面边缘） | `NAME` |
| 路线 | 中线 | `NAME`、`LENGTH`、`STA_START`、`STA_END`（桩号为纯数字） |
| 平台 | 位于平台高程的面 | `NAME`、`ELEV`、`AREA` |
| 坡脚线 | 带高程的线（平台和道路模型） | `NAME` |
| 道路模型特征线 | 带高程的线：中线、路面边缘、路肩 | `NAME`、`CODE`（CL、EOP_L、EOP_R、SH_L、SH_R） |
| 管道 | 从较高管底到较低管底的线 | `NAME`、`FROM`、`TO`、`DIA`、`DIA_UNIT`、`INV_UP`、`INV_DN`、`SLOPE`（百分比）、`LENGTH`、`NETWORK` |
| 构筑物 | 位于井口的点 | `NAME`、`RIM`、`INVERT`（该处最低的管底）、`SUMP`、`DIA`、`DIA_UNIT` |
| 每个 GIS 图层 | 按导入时的样子 | 其自身字段 |

长度、桩号和高程使用项目单位（美国测量英尺或米）。管道和构筑物直径在英尺项目中以英寸为单位，在米制项目中以毫米为单位；`DIA_UNIT` 指明所用单位。

## 格式

- **Shapefile**：一个 `.zip` 文件，内含每个类别的 shapefile（`.shp`、`.shx`、`.dbf`）、一个说明文本为 UTF-8 编码的 `.cpg` 文件，以及一个注明坐标系的 `.prj` 文件。带高程的图形以 shapefile 的 Z 类型写入。按格式要求，超过 10 个字符的字段名会被缩短，状态行会列出这些字段。
- **GeoPackage**：一个 `.gpkg` 文件，每个类别对应一张表，坐标系连同 EPSG 代码一起存储。只需一个文件而非多个，且保留较长的字段名。
- **KML** 或 **KMZ**（压缩的 KML）：一个经纬度 KML 文件（或压缩的 KMZ），供 Google Earth 和网页地图使用，每个类别为一个文件夹，每个要素为一个地标，以其 NAME 字段命名，所有字段作为扩展数据保存；高程以米为单位（海拔模式为绝对）。与 GeoJSON 一样，需要项目的坐标系。
- **GeoJSON**：一个经纬度文件（GeoJSON 标准只允许经纬度），每个要素带有 `kind` 属性（`pipes`、`structures` 等），便于接收方进行分类。高程按标准换算为米；仍以项目的垂直基准面为准（CivilCraft 没有大地水准面模型）。没有坐标系的项目无法导出 GeoJSON，对话框会说明原因。

## 格网，而非地面

GIS 部门以坐标系的**格网**坐标保存数据。若项目使用地面坐标或本地坐标（在{{ui:坐标}}中设置），导出时每个坐标都会换算回格网坐标：文件中的数值与平面图中的数值相差一个比例因子（对于本地坐标系，还相差一个旋转角）。点字段 `N` 和 `E` 同样保存格网值。对话框会予以提示。

:::tip
随文件附上简短说明：坐标系及其 EPSG 代码、高程的垂直基准面、单位，以及每个文件的内容。
:::

## 验证内容

- 所写的每个文件都已由 GDAL（大多数 GIS 程序用来读取这些文件的库）回读验证：每个图形、高程和属性、要素数量，以及以 EPSG 代码表示的坐标系（`.prj` 和 GeoPackage）。我们自己的读取程序也能正确读回这些文件。
- GeoJSON 文件遵循 RFC 7946：经度在前，纬度在后，不含 `crs` 成员，外环为逆时针，孔洞为顺时针；位置与 PROJ 的结果相差不超过 2 mm。
- 已导出一个地面坐标项目，并将每个点与其格网坐标逐一核对。
- 这些文件尚未在其他 GIS 程序中打开过。依赖之前，请先与部门核对首次交付的文件。
