မြို့နှင့် ကောင်တီ GIS ဌာနများသည် site context ကို GIS ဖိုင်များအဖြစ် ပေးသည်: မြေကွက်များ၊ easement များ၊ contour များ၊ utility များ၊ survey control။ CivilCraft က ၎င်းတို့အနက် သုံးမျိုးကို ဒီဇိုင်းအောက်တွင် plan ပေါ်ရှိ **GIS အလွှာများ** အဖြစ် ဖွင့်သည်။

| ဖိုင် | ဖွင့်ရမည့်အရာ |
|---|---|
| Shapefile | `.shp` နှင့် ၎င်း၏ `.shx`၊ `.dbf`၊ `.prj` နှင့် `.cpg` (အားလုံးကို ရွေးပါ)၊ သို့မဟုတ် ၎င်းတို့ ပါလာသော `.zip`။ shapefile အများအပြား ပါသော zip သည် အလွှာအများအပြား ပေးသည်။ |
| GeoJSON | `.geojson` ဖိုင် (ပထမစာကြောင်းများတွင် `FeatureCollection` သို့မဟုတ် `Feature` ပါသော `.json` ဖိုင်ကိုလည်း ရသည်)။ |
| GeoPackage | `.gpkg` ဖိုင်။ အတွင်းရှိ feature table အားလုံးကို စာရင်းပြသည်။ |
| KML သို့မဟုတ် KMZ | `.kml` ဖိုင် (Google Earth သို့မဟုတ် web map မှ) သို့မဟုတ် zip ထားသော `.kmz`။ folder တစ်ခုစီသည် အလွှာတစ်ခု ဖြစ်လာသည် (အမျိုးအစား အများအပြား ပါလျှင် point၊ line နှင့် polygon အဖြစ် ခွဲသည်); placemark ၏ အမည်၊ ဖော်ပြချက်နှင့် extended data တို့သည် attribute များ ဖြစ်လာသည်။ အမြင့်များသည် meter ဖြင့်ဖြစ်ပြီး GeoJSON ကဲ့သို့ latitude နှင့် longitude ဖြစ်သည်။ |

Point၊ multipoint၊ line၊ hole ပါသော polygon နှင့် multi-part ပုံသဏ္ဍာန်များကို ဖတ်သည်၊ ဖိုင်တွင် ရှိလျှင် ၎င်းတို့၏ elevation (z) များနှင့်အတူ။ Measure (M) တန်ဖိုးများကို ထားခဲ့သည်။ Elevation grid နှင့် LiDAR လည်း တူညီစွာ ဖွင့်သည်: [Elevation grid နှင့် LiDAR](topic:elevation-grids-and-lidar) ကို ကြည့်ပါ။

## ဖိုင်များ ဖွင့်ခြင်း

1. **GIS** အုပ်စုရှိ {{ui:Import}} ကို နှိပ်ပါ (သို့မဟုတ် {{ui:Open}}), ဖိုင်များကို ရွေးပါ၊ သို့မဟုတ် plan ပေါ်သို့ ချပါ။ ဖိုင်များကို ဤကွန်ပျူတာပေါ်တွင် ဖတ်သည်; ဘာမျှ upload မလုပ်ပါ။
2. **Import GIS data** dialog က တွေ့ရှိသော အလွှာတိုင်းကို စာရင်းပြသည်: ၎င်း၏ အမျိုးအစား၊ အင်္ဂါရပ် အရေအတွက် (geometry မရှိသော အရေအတွက်ပါ)၊ attribute field အရေအတွက်နှင့် ဖိုင်က ဖော်ပြသော coordinate system။ မလိုချင်သော အလွှာများကို အမှန်ခြစ်ဖြုတ်ပါ။
3. **Coordinate system** အပိုင်း (အောက်တွင်) နှင့် **What will happen** စာကြောင်းကို ဖတ်ပြီး {{ui:Import}} ကို နှိပ်ပါ။
4. အလွှာများသည် plan ပေါ်တွင်နှင့် ဘယ်ဘက် panel ရှိ **GIS layers** အောက်တွင် ပေါ်လာသည်။ သွင်းခြင်းသည် အဆင့်တစ်ခုဖြစ်ပြီး {{key:Mod+Z}} ဖြင့် ပြန်ဖျက်နိုင်သည်။

ဖိုင်ကြီးတစ်ခုတွင် plan အပေါ်တွင် တိုးတက်မှု စာကြောင်းနှင့် {{ui:Cancel}} ခလုတ် ပေါ်လာသည်။

## Coordinate system

GIS ဖိုင်များသည် coordinate system မှတစ်ဆင့် ၎င်းတို့၏ တည်နေရာကို ပြောသည် (shapefile ၏ `.prj`၊ GeoPackage ၏ spatial reference table; GeoJSON သည် အမြဲ latitude နှင့် longitude)။ CivilCraft က အလွှာတစ်ခုစီကို ၎င်း၏ ကိုယ်ပိုင်စနစ်မှ ပရောဂျက်၏ စနစ်သို့ ပြောင်းသည်။ ခန့်မှန်းခြင်း မလုပ်ပါ:

- **ပရောဂျက်တွင် coordinate system ရှိသည်** ({{ui:Coordinates}} တွင် သတ်မှတ်): ကိုယ်ပိုင်စနစ် ရှိသော အလွှာတိုင်းကို ထိုစနစ်သို့ ပြောင်းသည်၊ ground သို့မဟုတ် local ညှိမှုအပါအဝင်။ `.prj` မပါသော ဖိုင်တွင် ရွေးစရာ နှစ်ခု ရသည်: **Same as the project** (ကိန်းဂဏန်းများကို ရှိသည့်အတိုင်း တင်သည်) သို့မဟုတ် **Pick the file's system**။
- **ပရောဂျက်တွင် မရှိ၊ ဖိုင်သည် ပရောဂျက်ယူနစ်ဖြင့် projected စနစ်တွင် ရှိသည်** (ဥပမာ feet ပရောဂျက်အတွက် US survey feet ရှိ state plane zone): dialog က **Use that system as the project's coordinate system** ကို ပေးသည်။ ၎င်းကို သွင်းသည့် undo အဆင့်တစ်ခုတည်းတွင် သတ်မှတ်သည်။ ပရောဂျက်ထဲရှိ ဘာမျှ မရွှေ့ပါ; စနစ်က ကိန်းဂဏန်းများ၏ အဓိပ္ပာယ်ကိုသာ ပြောသည်။ ဒါအစား ပရောဂျက်အတွက် အခြားစနစ်ကို ရွေးနိုင်ပြီး အလွှာများကို ထိုစနစ်သို့ ပြောင်းသည်။
- **ပရောဂျက်နှင့် ဖိုင် နှစ်ခုစလုံးတွင် မရှိ**: ကိန်းဂဏန်းများကို ရှိသည့်အတိုင်း တင်ပြီး dialog က ထိုသို့ ပြောသည်။

Elevation များကိုလည်း ပြောင်းသည်: GeoJSON အမြင့်များသည် meter ဖြစ်သည် (GeoJSON စံနှုန်းအတိုင်း); အခြားဖိုင်များ၏ အမြင့်များကို ၎င်းတို့၏ ကိုယ်ပိုင်စနစ်ယူနစ်ဖြင့် ယူသည်။

:::warning
GeoJSON ဖိုင်ရှိ ±180° longitude သို့မဟုတ် ±90° latitude အပြင်ရှိ နေရာများသည် latitude နှင့် longitude မဟုတ်ပါ။ ထိုအင်္ဂါရပ်များကို ထုတ်ပစ်ပြီး dialog က အရေအတွက် ပြောသည်။ ထိုဖိုင်သည် များသောအားဖြင့် စနစ်မပါဘဲ သိမ်းထားသော projected ဖိုင် ဖြစ်သည်; ထပ်တောင်းပါ၊ သို့မဟုတ် `.prj` ပါသော shapefile ကို တောင်းပါ။
:::

NAD83 ကို WGS 84 နှင့် အတူတူဟု ယူဆသည် (GeoJSON သုံးသော စနစ်); ၎င်းတို့သည် မြောက်အမေရိကတွင် မီတာ အနည်းငယ် ကွာသောကြောင့် GeoJSON ဒေတာသည် ထိုမျှ ကွာနိုင်သည်။ အကောင်းဆုံး shift က grid ဖိုင် (ဥပမာ NAD27 အတွက် NADCON) လိုအပ်သည့်နေရာတွင် CivilCraft သည် ပိုကြမ်းသော ထုတ်ပြန်ထားသော shift ကို သုံးပြီး coordinate system dialog က ၎င်း၏ ကြမ်းပုံကို ပြသည် (NAD27 အတွက် ~20 m ခန့်)၊ grid ဖိုင်ကို ထည့်သည်အထိ: [Grid shift ဖိုင်များ](topic:coordinate-systems) ကို ကြည့်ပါ။

## GIS အလွှာများ

**GIS layers** အောက်ရှိ အတန်းတစ်ခုစီတွင်-

- အလွှာကို ပြ သို့မဟုတ် ဖျောက်ရန် checkbox (ဖျောက်ထားသော အလွှာများကို ရွေးလည်း မရပါ);
- ၎င်း၏အရောင် (စာရင်းမှ ရွေး);
- မီနူး (အစက်သုံးခု) တွင် {{ui:Zoom to}}, {{ui:Use for the surface…}}, {{ui:Rename…}} နှင့် {{ui:Remove}}။

ပြခြင်း၊ ဖျောက်ခြင်း၊ အရောင်ပြောင်းခြင်း၊ အမည်ပြောင်းခြင်းနှင့် ဖယ်ရှားခြင်းတို့သည် undo အဆင့်များ ဖြစ်သည်။ GIS အလွှာများကို ပရောဂျက်ဖိုင်တွင် သိမ်းပြီး ဖွင့်သည့်အခါ ပြန်ပေါ်လာသည်။ ၎င်းတို့သည် plan ၏ PDF plot နှင့် DXF၊ DWG export များထဲသို့လည်း ပါဝင်ပြီး တစ်ခုစီသည် `GIS-` နှင့် ၎င်း၏ နံပါတ်ဖြင့် အမည်ပေးထားသော layer ပေါ်တွင် ရှိသည်။

## Attribute မှ အညွှန်းတပ်ခြင်း

အလွှာ၏ {{ui:More}} မီနူး (**GIS layers** ရှိ အစက်သုံးခု) တွင် **Label with** အောက်မှ field တစ်ခုကို ရွေးပါ: အင်္ဂါရပ်တိုင်းသည် ၎င်း၏တန်ဖိုးကို အလွှာ၏အရောင်ဖြင့် plan ပေါ်တွင် ပြသည်။ point များကို point ဘေးတွင် အညွှန်းတပ်သည်၊ line များကို အရှည်ဆုံးအပိုင်း၏ အလယ်တွင် (ဘယ်မှ ညာသို့ ဖတ်နိုင်ရန် လှည့်ထားသည်) အညွှန်းတပ်သည်၊ polygon များကို အလယ်တွင် အညွှန်းတပ်သည်။ ဂဏန်းများသည် ဒသမ သုံးနေရာအထိ ပြသည်။ အညွှန်းများသည် စကေးမည်သို့ပင် ဖြစ်စေ စာရွက်ပေါ်တွင် 1.8 mm မြင့်ပြီး PDF plot၊ DXF နှင့် DWG တွင် ပါဝင်သည်။ ဖယ်ရန် **No labels** ကို ရွေးပါ; ပြောင်းလဲမှုတိုင်းသည် အဆင့်တစ်ခုဖြစ်ပြီး ({{key:Mod+Z}} ဖြင့် ပြန်ဖျက်နိုင်သည်)။ အလွှာတစ်ခုသည် အင်္ဂါရပ် 5,000 အထိသာ အညွှန်းတပ်နိုင်သည်။

## အင်္ဂါရပ်တစ်ခု ကြည့်ခြင်း

{{ui:Select}} ဖွင့်ထားစဉ် အင်္ဂါရပ်ကို နှိပ်ပါ။ **Properties** က ၎င်း၏ အလွှာ၊ ၎င်းက ဘယ်အင်္ဂါရပ်ဖြစ်သည်၊ ပုံသဏ္ဍာန် (အပိုင်း၊ hole၊ vertex)၊ elevation များ၊ ဆင်းသက်လာသည့် ဖိုင်နှင့် ထိုဖိုင်၏ coordinate system၊ ထို့နောက် attribute အားလုံးကို table ဖြင့် ပြသည်။ Attribute များသည် read-only ဖြစ်သည်: CivilCraft သည် GIS ဒေတာကို ရရှိခဲ့သည့်အတိုင်း ပြသည်၊ တည်းဖြတ်မပေးပါ။

pointer အောက်တွင် point နှင့် line နှစ်ခုစလုံး ရှိလျှင် point ကို ရွေးသည်; polygon အတွင်းတွင် အသေးဆုံး polygon ကို ရွေးသည်။

## မျက်နှာပြင်အတွက် အသုံးပြုခြင်း

အလွှာ၏ မီနူးကို ဖွင့်ပြီး {{ui:Use for the surface…}} ကို ရွေးပါ (သို့မဟုတ် **Properties** ရှိ ခလုတ်)။ ပေးသည့်အရာသည် အလွှာပေါ် မူတည်သည်:

| အလွှာ | ဖြစ်လာနိုင်သည် |
|---|---|
| အမြင့်ပါသော မျဉ်းများ (3D lines) | ၎င်းတို့၏ကိုယ်ပိုင် အမြင့်ဖြင့် breakline များ |
| အမြင့်မပါသော်လည်း number field ပါသော မျဉ်းများ (contour များ) | သင်ရွေးသော field ရှိ အမြင့်ဖြင့် breakline များ |
| Polygon များ | မျက်နှာပြင် နယ်နိမိတ် (ရွေးထားသော polygon၊ မဟုတ်လျှင် အကြီးဆုံး)၊ သို့မဟုတ် ၎င်းတို့၏ အနားများတလျှောက် breakline များ |
| အမြင့်ပါသော အမှတ်များ၊ သို့မဟုတ် elevation field ပါသော အမှတ်များ | survey point များ၊ အလွှာ၏ အမည်ဖြင့် ဖော်ပြထားပြီး point group ဖွဲ့သည် |

အသုံးပြုမှုတိုင်းသည် ဂျီသြမေတြီကို ပရောဂျက်ထဲသို့ ကူးထည့်သော undo အဆင့်တစ်ခု ဖြစ်ပြီး အလွှာကိုယ်တိုင် မပြောင်းပါ။ Elevation များကို ပရောဂျက်ယူနစ်ဖြင့် ယူသည်။

## Latitude နှင့် longitude ပါသော point ဖိုင်များ

header တွင် **latitude** နှင့် **longitude** column (`lat`, `latitude`, `lon`, `long`, `longitude`) ပါသော point ဖိုင်ကို northing နှင့် easting မဟုတ်ဘဲ ဒီဂရီဖြင့် ဖတ်သည်။ သွင်းသည့် dialog က ထိုသို့ ပြောသည်။ {{ui:Import}} တွင် point များကို ပရောဂျက်၏ coordinate system သို့ ပြောင်းသည်; စနစ်မရှိသော ပရောဂျက်က ရွေးဖို့ အရင်တောင်းသည်။ ဒီဂရီများကို feet အဖြစ် ဘယ်တော့မှ မသွင်းပါ။ latitude ±90° သို့မဟုတ် longitude ±180° အပြင်ရှိ row များကို အကြောင်းပြ၍ ငြင်းပယ်သည်။ elevation column ကို ပရောဂျက်ယူနစ်ဖြင့် ရှိသည့်အတိုင်း ယူသည်။

## Coordinate system အမည်ပေးထားသော LandXML ဖိုင်များ

သင်ဖွင့်သော LandXML ဖိုင်တွင် `CoordinateSystem` element (EPSG code၊ WKT ဖော်ပြချက် သို့မဟုတ် စနစ်အမည်) ရှိလျှင် CivilCraft က ၎င်းကို ပရောဂျက်၏ coordinate system အဖြစ် ကမ်းလှမ်းသည်။ လက်ခံလျှင် ဘာမျှ မရွှေ့ပါ; စနစ်က ကိန်းဂဏန်းများ၏ အဓိပ္ပာယ်ကိုသာ ပြောသည်။

## ဘာတွေ စစ်ဆေးပြီးပြီလဲ

- reader တိုင်းကို GDAL (GIS ပရိုဂရမ်အများစု သုံးသော library) နှင့် နှိုင်းယှဉ်ထားသည်၊ GDAL ရေးထားသော ဖိုင်များပေါ်တွင်: elevation ပါနှင့် မပါသော shapefile အမျိုးအစားအားလုံး၊ multi-part line များ၊ hole ပါသော polygon များ၊ ဗလာ geometry များ၊ စာသား၊ number၊ date နှင့် true/false attribute များ၊ `.cpg` ပါနှင့်မပါ UTF-8 နှင့် Windows-1252 စာသား၊ shapefile အများအပြား ပါသော zip၊ geometry အမျိုးအစားအားလုံးပါသော GeoJSON၊ table လေးခုပါသော GeoPackage။ geometry၊ elevation နှင့် attribute တိုင်း ကိုက်ညီသည်။
- latitude နှင့် longitude မှ နှင့် UTM မှ ပြောင်းထားသော နေရာများကို PROJ (GDAL နောက်ကွယ်ရှိ projection library) နှင့် 3 mm အတွင်း ကိုက်ညီသည်။
- ပျက်စီးနေသော ဖိုင်များ (ဖြတ်တောက်ထား၊ အရွယ်အစားကို မှန်အောင်မပြသော၊ zip မကောင်း၊ GeoPackage မကောင်း) သည် ရိုးရှင်းသော စာတစ်ကြောင်းသာ ပေးပြီး ဘာမျှ မရပ်တန့်ပါ။
- ဤအရာများကို အခြား GIS ပရိုဂရမ်များတွင် မဖွင့်ရသေးပါ၊ file geodatabase၊ KML နှင့် KMZ ကိုလည်း မဖတ်ရသေးပါ ([မတည်ဆောက်ရသေးသည်များ](topic:not-built-yet) ကို ကြည့်ပါ)။
