အများပြည်သူ အသုံးပြုနိုင်သော အမြင့်ဒေတာ နည်းလမ်း နှစ်မျိုးရှိသည်: **elevation grid များ** (DEM: cell တစ်ခုစီအတွက် အမြင့်တစ်ခု၊ များသောအားဖြင့် GeoTIFF `.tif` သို့မဟုတ် ASCII grid `.asc`) နှင့် **LiDAR point များ** (`.las` ဖိုင်ထဲရှိ laser return သန်းပေါင်းများစွာ၊ ချုံ့ထားလျှင် `.laz`)။ CivilCraft က နှစ်မျိုးလုံးကို ဘရောက်ဇာအတွင်းတွင် survey point များ သို့မဟုတ် မျက်နှာပြင်အဖြစ် ပြောင်းသည်: ဘာမျှ upload မလုပ်ပါ။

## ဖိုင်ဖွင့်ရန်

1. {{ui:Open}} (သို့မဟုတ် GIS အုပ်စုရှိ {{ui:Import}}) ကို နှိပ်ပြီး ဖိုင်ကို ရွေးပါ၊ သို့မဟုတ် ပလန်ပေါ်သို့ ဆွဲချပါ။ ASCII grid အတွက် ၎င်း၏ `.prj` ဖိုင်ကိုလည်း ရွေးပါ၊ CivilCraft က coordinate system ကို သိနိုင်စေရန်ဖြစ်သည်။
2. Import dialog က ဖိုင်က ကိုယ်ဖြစ်ကြောင်း ပြသသည်: အရွယ်အစား၊ cell သို့မဟုတ် point အရေအတွက်၊ coordinate system၊ latitude နှင့် longitude တွင် တည်နေရာ၊ နှင့် အမြင့် အကွာအဝေး။ LiDAR အတွက် ပထမဦးစွာ point တိုင်းကို တစ်ကြိမ်ဖတ်ပြီး **class** များကို ရေတွက်သည် (progress bar က မည်မျှ ရောက်သည်ကို ပြသသည်; {{ui:Cancel}} က ရပ်စေသည်)။

အနီရောင်၊ အစိမ်းရောင်၊ အပြာရောင် (သုံးလွှာ သို့မဟုတ် လေးလွှာ) ပါသော GeoTIFF သည် ပုံတစ်ပုံ ဖြစ်ပြီး အမြင့်များ မဟုတ်ပါ: ၎င်းကို မြေပုံ လေယာများထဲ ထည့်သည်။

## ဘာကို သွင်းမလဲ ရွေးရန်

- **နယ်ပယ်**: {{ui:The project’s extents and a margin}} (margin ကို ရိုက်ပါ), {{ui:What the plan shows now}}, သို့မဟုတ် {{ui:The whole file}}။ ဖိုင်၏ ထိုအပိုင်းကိုသာ ဖတ်သည်။
- **လျှော့ချရန်**: သင်ရမည့် point များကြား အကွာအဝေး၊ ပရောဂျက်၏ ယူနစ်ဖြင့်။ ဆက်တင်များအောက်ရှိ မျဉ်းက သင်ရိုက်သည့်အခါ ထို အကွာအဝေးက point မည်မျှ ပေးမည်ကို ပြသသည်။ Grid အတွက် CivilCraft က cell ၂ ခု၊ ၃ ခု … ခြားတစ်ခုစီကို ထားသည်၊ ထို့ကြောင့် အမြင့်များသည် ဖိုင်၏ တိကျသော တန်ဖိုးအတိုင်း ရှိနေသည်; cell များကို ပျမ်းမျှ မယူပါ။ LiDAR အတွက် နယ်ပယ်ကို ထို အရွယ်အစား၏ စတုရန်းများအဖြစ် ခွဲပြီး စတုရန်းတစ်ခုလျှင် point တစ်ခု ထားသည်: {{ui:The point nearest each cell’s center}} (ပုံမှန်), {{ui:The lowest point in each cell}} (ဖိုင်တွင် ground class မရှိလျှင် ကောင်းသည်: မြေပြင်သည် သစ်ပင်အောက်တွင် ရှိသည်), သို့မဟုတ် {{ui:The average of each cell’s points}}။
- **Class များ** (LiDAR): ground (class 2) ကို ဖိုင်တွင် ပါလျှင် အမှန်ခြစ်သည်; ဆောက်လုပ်ချက်၊ သစ်ပင်နှင့် noise များကို ထုတ်ထားသည်။ Ground class မရှိလျှင် class အားလုံးကို အမှန်ခြစ်ပြီး dialog က ထိုသို့ ပြောသည်။
- **မြေပြင်** (LiDAR, 0.8): drone cloud တွင် ground class မရှိ။ ဖိုင်တွင် မရှိလျှင် dialog သည် {{ui:Find the ground myself (drone clouds, no ground class)}} ဖြင့် စတင်သည်: noise မှလွဲ၍ class အားလုံးကို ဖတ်ပြီး cell တစ်ခုစီရှိ အနိမ့်ဆုံး point ကို ထားသည်၊ ထို့နောက် CivilCraft က progressive morphological filter (Zhang နှင့် အခြား၊ 2003) ဖြင့် ဆောက်လုပ်ချက်၊ သစ်ပင်နှင့် ပျံ့လွင့်နေသော အနိမ့် point များကို ဖယ်ရှားသည်။ ထိုစစ်ထုတ်မှုကို သင် ထိန်းချုပ်နိုင်သည်: **Largest object to take out** (အကြီးဆုံး ဆောက်လုပ်ချက်၏ အကျယ်; ပြတင်းပေါက်များသည် ၎င်းကို ဖုံးသည်အထိ ကြီးလာသည်; 0 သည် 20 cell ကို ဆိုလိုသည်) နှင့် **Steepest ground slope**။ အလုပ်ကို အနိမ့်ဆုံး point များ၏ grid ပေါ်တွင် လုပ်သဖြင့် point သန်းပေါင်းများစွာ ရှိသော cloud သည် cell အရေအတွက်ထက် ပိုမကုန်ကျပါ (ဖြတ်သန်းဖတ်ခြင်း တစ်ကြိမ်သာ)။ အကွာအဝေးသည် cell ဖြစ်သည်: ပိုကြမ်းသော cell သည် ပိုမြန်ပြီး သေးငယ်သော အရာများကို ပိုလွတ်စေသည်၊ ပိုနုသော cell က မြေပြင် အသေးစိတ် ပိုထိန်းသည်။ အစီရင်ခံစာက မြေပြင်အဖြစ် ထိန်းထားသော point အရေအတွက်၊ objects အဖြစ် ဖယ်ရှားသော cell အရေအတွက်၊ နှင့် ပစ်ချလိုက်သော ပျံ့လွင့်နေသော အနိမ့် point အရေအတွက်ကို ပြသသည်။ ပုံတုပ် 300 m drone survey (ဆောက်လုပ်ချက် ငါးခု၊ သစ်ပင် 70၊ အနိမ့် outlier 200) တွင် ထိန်းထားသော point များသည် မှန်ကန်သော မြေပြင်မှ 3 cm အတွင်း ရှိပြီး မည်သည့် အမိုးမျှ သို့မဟုတ် အပင်ထုတ်ကို ထိန်းမထားပါ။
- **ဖိုင်ထဲရှိ အမြင့်များ**: meter၊ feet သို့မဟုတ် US survey feet။ ဖိုင်က ပြောလျှင် ယူနစ်ကို ရွေးပြီးသား ဖြစ်သည်။ မပြောလျှင် သင်ရွေးရမည်: dialog က အမြင့် အကွာအဝေးကို နည်းလမ်းနှစ်မျိုးဖြင့် ပြသသည် ထို့ကြောင့် နေရာနှင့် ဘယ်ဟာ သင့်တော်သည်ကို ခွဲခြားနိုင်သည်။
- **Import as** (grid များအတွက်သာ): {{ui:Survey points (description DEM)}}, သို့မဟုတ် {{ui:The surface itself (a grid of triangles)}}။

Import တစ်ကြိမ်တွင် point 500,000 ထက် မပိုသွင်းနိုင်ပါ။ ရွေးချယ်မှုက ထိုထက်ပိုလျှင် dialog က အဘယ်မျှပိုသည်နှင့် မည်သည့် အကွာအဝေးက သင့်တော်မည်ကို ပြောပြပြီး {{ui:Import}} ကို မနှိပ်နိုင်တော့ပါ။

{{ui:Import}} ကို နှိပ်ပါ။ Progress bar က ဖတ်နေမှုကို ပြသသည်; {{ui:Cancel}} က ရပ်စေပြီး ဘာမျှ မပြောင်းပါ။

:::warning
ဒေါင်လိုက် ယူနစ်သည် အသုံးများသော ထောင်ချောက်တစ်ခုဖြစ်သည်။ DEM အများအပြားတွင် state plane easting နှင့် northing သည် feet ဖြစ်သော်လည်း အမြင့်သည် meter ဖြစ်သည်။ dialog ပြသသော အကွာအဝေးကို သင်သိသော နေရာနှင့် နှိုင်းယှဉ်ပါ။
:::

## သင်ရရှိမည့်အရာ

- **Survey point များ**: သင်၏ အမြင့်ဆုံး point နံပါတ်၏ နောက်မှ နံပါတ်ပေးထားပြီး ဖော်ပြချက် `DEM` (grid) သို့မဟုတ် `LIDAR` ဖြင့်၊ ထို့ကြောင့် **Points** အောက်တွင် point group တစ်ခုအဖြစ် ရှိပြီး အခြား point များကဲ့သို့ မျက်နှာပြင်ကို တည်ဆောက်သည်။ ၎င်းတို့ကို သွင်းခြင်းသည် အဆင့်တစ်ခုဖြစ်သည်: {{key:Mod+Z}} က ပြန်ဖယ်ရှားသည်။
- **မျက်နှာပြင်ကိုယ်တိုင်**: grid TIN၊ cell တစ်ခုလျှင် တြိဂံ ၂ ခု၊ တောင်အနောက်မှ မြောက်အရှေ့ ဖြတ်မျဉ်းဖြင့် ခွဲထားသည်။ ဒေတာမရှိသော corner ပါသော တြိဂံကို ဖယ်ထုတ်သည်၊ ထို့ကြောင့် ဒေတာ၏ အပေါက်များသည် အပေါက်အဖြစ် ကျန်သည်။ မျက်နှာပြင်သည် grid point တိုင်းတွင် grid နှင့် ညီပြီး တြိဂံတစ်ခုစီအတွင်း ပြားသော ပလိန်ဖြစ်သည်။ ၎င်းသည် ပရောဂျက်၏ မျက်နှာပြင်ကို အစားထိုးသည် (dialog က အရင်မေးသည်); {{key:Mod+Z}} က ယခင် မျက်နှာပြင်ကို ပြန်ယူသည်။ ဘယ်ဘက်ပြား ခေါင်းစဉ်က **Surface (elevation grid မှ)** ဟု ပြသသည်။

## Coordinate system များ

- ပရောဂျက်တွင် coordinate system ရှိပြီး ဖိုင်က အခြားတစ်ခုကို ပြောလျှင် point တိုင်းကို ပရောဂျက်၏ system သို့ (ရှိလျှင် ၎င်း၏ ground သို့မဟုတ် local coordinates သို့လည်း) ပြောင်းသည်။
- ပရောဂျက်တွင် မရှိပြီး ဖိုင်၏ system သည် ပရောဂျက်၏ ယူနစ် (feet သို့မဟုတ် meter) ဖြင့် ဖြစ်လျှင် dialog က ၎င်းကို ပရောဂျက် coordinate system အဖြစ် ပြုလုပ်ရန် ကမ်းလှမ်းသည်၊ point များနှင့် တူညီသော undo အဆင့်တွင်။
- ဖိုင်သည် latitude နှင့် longitude ဖြစ်လျှင်၊ သို့မဟုတ် feet ပရောဂျက်အတွက် meter ဖြစ်လျှင် dialog က ပရောဂျက် coordinate system ကို အရင်ရွေးရန် တောင်းဆိုသည်။
- ဖိုင်က မပြောလျှင် ၎င်း၏ နံပါတ်များကို ပရောဂျက်၏ coordinates အဖြစ် ယူသည်။ ဖိုင်၏ system ကို ရွေးနိုင်သည်။

## မျက်နှာပြင်ကို GeoTIFF အဖြစ် ထုတ်ရန်

1. GIS အုပ်စုရှိ {{ui:Export}} ကို နှိပ်ပါ။
2. GeoTIFF အပိုင်းတွင် မျက်နှာပြင် (လက်ရှိ မြေပြင် သို့မဟုတ် ဖြတ်ထားသော မျက်နှာပြင်) နှင့် cell အရွယ်အစားကို ရွေးပါ။ ပုံမှန်တန်ဖိုးက မျက်နှာပြင်၏ တြိဂံ ပျမ်းမျှ ဘောင်မှ ရသည်။ Dialog က ရေးမည့် grid ၏ အရွယ်အစားကို ပြသသည်။
3. {{ui:Download GeoTIFF}} ကို နှိပ်ပါ။

ဖိုင်သည် ပရောဂျက် ယူနစ်ဖြင့် 32-bit floating point အမြင့်များ၏ band တစ်ခု ဖြစ်ပြီး မျက်နှာပြင်၏ extent အပေါ်တွင် ရှိသည်; မျက်နှာပြင်အပြင်ရှိ cell များသည် "no data" (−3.4028235e38) ဖြစ်သည်။ Cell တစ်ခုစီ၏ တန်ဖိုးသည် cell ၏ ဗဟိုရှိ မျက်နှာပြင်၏ အမြင့်ဖြစ်သည်။ Coordinates များသည် **grid** coordinates ဖြစ်သည်: ground သို့မဟုတ် local coordinates ရှိ ပရောဂျက်ကို grid သို့ ပြန်ပြောင်းသည်။ ဖိုင်က ပရောဂျက်၏ coordinate system ကို EPSG code ဖြင့် ဖော်ပြသည်; EPSG code မရှိသော system ကို မရေးပါ၊ dialog က GIS ဌာနသို့ မည်သည့် system ဖြစ်ကြောင်း ပြောရန် သတိပေးသည်။

## စစ်ဆေးပြီးသော အရာများ

- GeoTIFF နှင့် ASCII grid reader များကို GDAL (rasterio မှတစ်ဆင့်) ဖြင့် စစ်ဆေးထားသည်၊ GIS ပရိုဂရမ်အများစုက ဤဖိုင်များကို ဖတ်ရာတွင် သုံးသော library ဖြစ်သည်: 32-bit float နှင့် 16-bit integer grid များ၊ tiled နှင့် stripped၊ DEFLATE နှင့် LZW၊ nodata၊ scale နှင့် offset၊ pixel-is-point၊ UTM grid၊ US survey feet ရှိ state plane grid နှင့် latitude/longitude grid — တန်ဖိုးအားလုံး ညီသည်။
- LAS နှင့် LAZ reader များကို laspy ဖြင့် စစ်ဆေးထားသည်: LAS 1.2 နှင့် 1.4၊ point format 0၊ 1၊ 3၊ 6၊ 7 နှင့် 8၊ coordinate system ပါသည်ဖြစ်စေ မပါသည်ဖြစ်စေ၊ နှင့် LASzip-compatible backend ဖြင့် ရေးထားသော LAZ — point အားလုံး ညီသည်။
- ပြောင်းထားသော coordinates များကို PROJ ဖြင့် 1 mm အတိအကျ စစ်ဆေးထားသည်။
- ထုတ်ထားသော GeoTIFF များကို GDAL ဖြင့် ပြန်ဖတ်ထားသည်: coordinate system၊ cell နေရာများ၊ nodata၊ ယူနစ်များနှင့် တန်ဖိုးများ မျက်နှာပြင်နှင့် 0.0001 အတွင်း ညီသည်။
- ဤအရာများကို အခြား GIS သို့မဟုတ် CAD ပရိုဂရမ်များတွင် မဖွင့်ရသေးပါ။

## မတည်ဆောက်ရသေးသော အရာများ

- အမြင့်ဒေတမ် ပြောင်းလဲမှု (geoid မော်ဒယ်များ): အမြင့်များကို ဖိုင်တွင်ရှိသည့်အတိုင်း သုံးသည်။
- Waveform ဒေတာ၊ class အလိုက်မဟုတ်သော LiDAR return များ၊ အရောင်များနှင့် intensity များ။
- Band အများအပြား၊ overview များ၊ သို့မဟုတ် 200 MB ထက်ကြီးသော ဖိုင်များ။
- LAS သို့မဟုတ် LAZ ကို မျက်နှာပြင်မှ သို့မဟုတ် ဤကိရိယာမှ ရေးခြင်း ([Point cloud](topic:point-clouds) add-on က သန့်စင်ထားသော cloud ကို LAS 1.4 သို့မဟုတ် LAZ အဖြစ် ရေးသည်)။
