ແບບສຳຫຼວດອາດເບິ່ງຖືກຕ້ອງ ແຕ່ຍັງຜິດສຳລັບພື້ນດິນໜຶ່ງ: ຫົວໜ່ວຍຂອງມັນອາດຖືກເດົາ, ເສັ້ນຊັ້ນລະດັບອາດຢູ່ລາບທີ່ຄວາມສູງ 0, ຫຼື ລະດັບຂອງມັນອາດຂຽນເປັນຂໍ້ຄວາມທີ່ບໍ່ແມ່ນເລຂາຄະນິດເລີຍ. ພາກ **ລະດັບສຳຫຼວດ ແລະ ການກວດສອບ** ຂອງກ່ອງໂຕ້ຕອບ {{ui:ເສັ້ນແບບແຕ້ມ}} (ເບິ່ງ [ເປີດ DWG ຫຼື DXF ເປັນເສັ້ນແບບແຕ້ມ](topic:open-dwg-dxf)) ອ່ານລະດັບເຫຼົ່ານັ້ນ ແລະ ບອກທ່ານວ່າມີຫຍັງເບິ່ງຜິດ ກ່ອນທີ່ຈະເພີ່ມຫຍັງ.

## ລະດັບທີ່ຂຽນເປັນຂໍ້ຄວາມ ຫຼື ໃນ attributes

ແບບສຳຫຼວດຫຼາຍອັນໃຫ້ລະດັບຈຸດເປັນຂໍ້ຄວາມນ້ອຍໆຢູ່ຂ້າງເຄື່ອງໝາຍກາແບບຂ້າມ, ເຊັ່ນ `104.37` ຫຼື `EL 104.37`, ຫຼື ເປັນ attribute ຂອງບລັອກຈຸດ. ອັນເຫຼົ່ານີ້ບໍ່ແມ່ນເສັ້ນ, ສະນັ້ນຕົວອ່ານເສັ້ນແບບແຕ້ມຈະບໍ່ລວມພວກມັນ. ພາກນີ້ລາຍຊື່ຈຳນວນທີ່ພົບ ແລະ ໃຫ້ທ່ານນຳມາເປັນ **ຈຸດສຳຫຼວດ**:

1. ຕິກ **ເອົາ … ລະດັບເປັນຈຸດສຳຫຼວດ**. ມັນບໍ່ຖືກຕິກຕອນເລີ່ມ, ເພາະບໍ່ແມ່ນທຸກຕົວເລກໃນແບບແປນຈະເປັນຄວາມສູງ.
2. ຂໍ້ຄວາມຈະຖືກອ່ານເມື່ອມັນເປັນລະດັບດ້ວຍຕົວຂອງມັນເອງ: ຕົວເລກທີ່ມີສ່ວນທົດສະນິຍົມ (`104.37`, `+104,37`, `-3.50`), ຫຼື ຕົວເລກຫຼັງ `EL`, `ELEV`, `RL`, `FFL`, `GL`, `TW`, `BW`, `INV`, `Z` ຫຼື `LEVEL`, ພ້ອມກັບ `m`, `ft` ຫຼື `'` ທີ່ຕາມຫຼັງໄດ້ຕາມໃຈ. ຕົວເລກຕົວດຽວທີ່ເປັນຈຳນວນເຕັມ (`12`) ຖືກອ່ານເປັນໝາຍເລກຕອນດິນ ຫຼື ແຜ່ນ, ບໍ່ແມ່ນລະດັບ; ຂໍ້ຄວາມເຊັ່ນ `GATE 3` ຫຼື ວັນທີ ບໍ່ເຄີຍຖືກອ່ານ. ລະຫັດຈັດຮູບແບບຂໍ້ຄວາມຖືກຂ້າມໄປ.
3. ສຳລັບ attributes ຂອງບລັອກ, ເລືອກ **ແອັດທຣິບິວທີ່ເກັບລະດັບ**. CivilCraft ຊອກ tag ຊື່ ELEV, Z, LEVEL, RL ຫຼື ຄ້າຍຄືກັນໄດ້ເອງ; ເລືອກອັນອື່ນຈາກລາຍການຖ້າແບບໃຊ້ຊື່ຂອງຕົນເອງ. ການເລືອກຈະຖືກຈື່ໄວ້ສຳລັບຊື່ໄຟລ໌ນັ້ນໃນຄອມພິວເຕີນີ້, ສະນັ້ນເປີດມັນອີກຄັ້ງຈະເລີ່ມທີ່ tag ດຽວກັນ. tag ທີ່ທ່ານເລືອກຈະຖືເອົາຕົວເລກຈຳນວນເຕັມເປັນລະດັບດ້ວຍ.
4. ກົດ {{ui:ເພີ່ມ}}. ຈຸດຕ່າງໆຈະຖືກໃສ່ໝາຍເລກຕໍ່ຈາກໝາຍເລກສູງສຸດໃນໂຄງການ, ແຕ່ລະຈຸດຖືກອະທິບາຍດ້ວຍເລເຢີ (ຫຼື ບລັອກ) ຂອງມັນ, ແລະ ລະດັບຖືກແປງເປັນຫົວໜ່ວຍຂອງໂຄງການເໝືອນແບບແປນທັງໝົດ. ທັງໝົດນີ້ເປັນຂັ້ນຕອນດຽວ: {{key:Mod+Z}} ລຶບຈຸດເຫຼົ່ານັ້ນອອກ.

ຂໍ້ຄວາມຢູ່ທີ່ຈຸດແຊກຂອງມັນເອງ (ຫຼື ຈຸດຈັດແນວຖ້າມີ). ຂໍ້ຄວາມພາຍໃນບລັອກບໍ່ຖືກອ່ານ, ແລະ ແບບແປນບໍ່ເຄີຍຖືກປ່ຽນແປງ.

## ການກວດສອບ

ການກວດສອບເຮັດວຽກກັບສິ່ງທີ່ທ່ານກຳລັງຈະນຳເຂົ້າ ແລະ ລາຍຊື່ສິ່ງທີ່ພົບ, ໜຶ່ງແຖວສຳລັບແຕ່ລະປະເພດບັນຫາ:

| ມັນບອກວ່າ | ມັນໝາຍເຖິງຫຍັງ |
|---|---|
| **ຫົວໜ່ວຍບໍ່ໄດ້ລະບຸ** | ແບບບໍ່ໄດ້ລະບຸຫົວໜ່ວຍ, ສະນັ້ນຕົວເລກຂອງມັນຖືກອ່ານເປັນຫົວໜ່ວຍຂອງໂຄງການ. ກວດໄລຍະໜຶ່ງທີ່ທ່ານຮູ້. |
| **ຫົວໜ່ວຍຖືກແປງ** | ຫົວໜ່ວຍຂອງແບບແຕກຕ່າງຈາກໂຄງການ ແລະ ຖືກປັບຂະໜາດ (ເປັນໝາຍເຫດ, ບໍ່ແມ່ນຄວາມຜິດພາດ). |
| **ຂໍ້ມູນກວມພື້ນທີ່ … km** ຫຼື **… m** | ຂອບເຂດຂອງຂໍ້ມູນໃຫຍ່ກວ່າ 200 km ຫຼື ນ້ອຍກວ່າເຄິ່ງແມັດ, ເຊິ່ງປົກກະຕິໝາຍເຖິງຫົວໜ່ວຍຜິດ (ມິນລີແມັດອ່ານເປັນແມັດ, ຫຼື ກັບກັນ). |
| **ບໍ່ມີລະບົບພິກັດ** | ໂຄງການບໍ່ມີ. ເປັນຄຳເຕືອນເມື່ອຂໍ້ມູນຢູ່ໄກຈາກສູນ, ເຊັ່ນພິກັດ state plane ຫຼື national grid. ເບິ່ງ [ລະບົບພິກັດ](topic:coordinate-systems). |
| **ໄກຈາກຈຸດກຳເນີດ** | ຂໍ້ມູນຢູ່ເກີນ 100 km ຈາກສູນ. ໄກຈາກສູນ, ມຸມມອງ 3D ແລະ ການສົ່ງອອກຈະສູນເສຍຄວາມແມ່ນຍຳ ແລະ ສັ່ນ. |
| **ເລເຢີເສັ້ນຊັ້ນລະດັບ … ບໍ່ມີຄວາມສູງ** | ເລເຢີທີ່ຊື່ຄືເສັ້ນຊັ້ນລະດັບ (TOPO, CONT, CNTR, CONTOUR) ມີເສັ້ນທີ່ຄວາມສູງ 0, ສະນັ້ນພື້ນດິນທີ່ສ້າງຈາກພວກມັນຈະລາບ. |
| **ລະດັບເປັນ 0 ພໍດີ** | ບາງລະດັບເປັນ 0 ໃນຂະນະທີ່ລະດັບປົກກະຕິຢູ່ໄກຈາກນັ້ນ: ອາດເປັນຄວາມສູງທີ່ຫາຍໄປ. |
| **ລະດັບຢູ່ໄກຈາກອັນອື່ນ** | ບາງລະດັບຢູ່ນອກຂອງອັນອື່ນ (ວັດຈາກກາງຂອງລະດັບທັງໝົດ, ສະນັ້ນສະຖານທີ່ລາດຊັນທີ່ມີຊ່ວງກວ້າງຈະບໍ່ຖືກໝາຍ), ຫຼື ສູງກວ່າ 9,000 m ຫຼື ຕ່ຳກວ່າ -11,000 m. |
| **ຈຸດຢູ່ທັບກັບຈຸດອື່ນ** | ສອງຈຸດຢູ່ບ່ອນດຽວກັນທີ່ມີລະດັບດຽວກັນ, ຫຼື ມີລະດັບຕ່າງກັນ. |

ຫຼັງຈາກທ່ານກົດ {{ui:ເພີ່ມ}}, ແຖວດຽວກັນຈະໄປ **ບັນຫາ**, ໜຶ່ງອັນສຳລັບແຕ່ລະປະເພດ, ພ້ອມຊື່ໄຟລ໌, ເພື່ອໃຫ້ທ່ານກັບມາເບິ່ງໄດ້. ການກວດສອບຕັດສິນແບບ; ມັນບໍ່ປ່ຽນແປງຫຍັງໃນມັນ, ແລະ ບໍ່ຢຸດທ່ານຈາກການໃຊ້ແບບ.

:::tip
ເມື່ອການກວດສອບບອກວ່າເສັ້ນຊັ້ນລະດັບລາບທີ່ 0 ແລະ ມີລະດັບທີ່ຂຽນເປັນຂໍ້ຄວາມ, ໃຫ້ເອົາລະດັບເປັນຈຸດສຳຫຼວດ: ມັນມັກຈະມີຄວາມສູງຈິງທີ່ເສັ້ນຊັ້ນລະດັບຂາດ.
:::

## ສິ່ງທີ່ບໍ່ໄດ້ກວດ

ການກວດສອບບໍ່ປຽບທຽບແບບກັບການສຳຫຼວດທີ່ສອງ, ແລະ ມັນບໍ່ສາມາດບອກໄດ້ວ່າແບບຢູ່ໃນລະບົບພິກັດໃດ: ມັນພຽງແຕ່ບອກທ່ານວ່າບໍ່ມີການຕັ້ງຄ່າໃດເລີຍ.
