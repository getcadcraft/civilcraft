許多市政府與縣政府會在專案結案時，要求以 GIS 格式提供竣工資料：管線與構造物的位置、最終整地高程、道路中心線。**GIS › 匯出**會將 CivilCraft 所保存的內容寫成 GIS 圖層，每種物件類型一個圖層。

## 匯出前

1. 在{{ui:座標}}中設定專案的座標系統。GIS 部門必須知道數值所在的位置；若沒有座標系統，檔案只會帶有專案自身的數值，且不會註明任何座標系統。
2. 檢查曲面、路線、平台與管線網路，確定交付的內容符合需求。
3. 向對方的 GIS 部門詢問所需的格式與座標系統。許多單位仍要求使用當地 state plane 分區的 shapefile；較新的系統則接受 GeoPackage。

## 匯出

1. 在**GIS**群組中按一下{{ui:匯出}}。
2. 在**匯出項目**下勾選要送出的類別。每個類別會顯示其地物數量；尚無地物的類別會呈灰色。
3. 在**格式**下選擇檔案格式。
4. 閱讀有關座標與單位的說明，然後按一下下載按鈕。狀態列會說明寫入了哪些內容，以及哪些欄位名稱被縮短。

此對話方塊也包含高程格網匯出（{{ui:以 GeoTIFF 高程格網匯出曲面}}）；請見[高程格網與 LiDAR](topic:elevation-grids-and-lidar)。

## 各類別的內容

| 類別 | 形狀 | 欄位 |
|---|---|---|
| 測量點 | 具高程的點 | `P` 點號、`N` 北座標、`E` 東座標、`Z` 高程、`D` 描述 |
| 原地面與整地後曲面的等高線 | 依其高程的線 | `ELEV` |
| 斷線 | 具高程的線 | `NAME` |
| 曲面邊界 | 面（繪製的邊界，否則為曲面的邊緣） | `NAME` |
| 路線 | 中心線 | `NAME`、`LENGTH`、`STA_START`、`STA_END`（樁號為純數字） |
| 平台 | 位於平台高程的面 | `NAME`、`ELEV`、`AREA` |
| 坡腳線 | 具高程的線（平台與道路模型） | `NAME` |
| 道路模型特徵線 | 具高程的線：中心、路面邊緣、路肩 | `NAME`、`CODE`（CL、EOP_L、EOP_R、SH_L、SH_R） |
| 管線 | 由上游管底到下游管底的線 | `NAME`、`FROM`、`TO`、`DIA`、`DIA_UNIT`、`INV_UP`、`INV_DN`、`SLOPE`（百分比）、`LENGTH`、`NETWORK` |
| 構造物 | 位於井緣的點 | `NAME`、`RIM`、`INVERT`（該處最低的管底）、`SUMP`、`DIA`、`DIA_UNIT` |
| 各 GIS 圖層 | 依匯入時的形式 | 其自身的欄位 |

長度、樁號與高程以專案單位（美制測量英尺或公尺）表示。管線與構造物的直徑，英尺專案以英吋、公尺專案以毫米表示；`DIA_UNIT` 會註明單位。

## 檔案格式

- **Shapefile**：一個 `.zip`，內含每個類別一組 shapefile（`.shp`、`.shx`、`.dbf`）、一個說明文字為 UTF-8 的 `.cpg`，以及一個註明座標系統的 `.prj`。具高程的形狀會寫成 shapefile 的 Z 類型。依格式要求，超過 10 個字元的欄位名稱會被縮短，狀態列會列出這些名稱。
- **GeoPackage**：一個 `.gpkg` 檔，每個類別一張資料表，座標系統以其 EPSG 代碼儲存。以一個檔案取代多個檔案，並保留較長的欄位名稱。
- **KML** 或 **KMZ**（壓縮的 KML）：一個以經緯度表示的檔案，供 Google Earth 與網路地圖使用，每個類別為一個資料夾，每個地物為一個地標，以其 NAME 欄位命名，所有欄位都作為擴充資料；高度以公尺表示（高度模式為絕對）。與 GeoJSON 相同，它需要專案的座標系統。
- **GeoJSON**：一個以經緯度表示的檔案（GeoJSON 標準只允許此種表示），每個地物都帶有 `kind` 屬性（`pipes`、`structures`、…），讓接收方可以加以區分。高度依標準轉換為公尺；它們仍保留在專案的垂直基準上（CivilCraft 沒有大地水準面模型）。沒有座標系統的專案無法匯出 GeoJSON，對話方塊會說明原因。

## 格網，而非地面

GIS 部門會以座標系統的**格網**座標保存資料。若專案使用地面座標或局部座標（於{{ui:座標}}中設定），匯出時每個座標都會換算回格網：檔案中的數值會與平面圖上的數值相差一個專案比例尺係數（若為局部座標系統，還會有旋轉）。點欄位 `N` 與 `E` 也會保存格網值。對話方塊會提醒此事。

:::tip
隨檔案附上簡短說明：座標系統及其 EPSG 代碼、高程的垂直基準、單位，以及每個檔案的內容。
:::

## 驗證內容

- 所寫出的每個檔案都已由 GDAL 讀回驗證。GDAL 是多數 GIS 程式用來讀取這些檔案的函式庫。驗證項目包括：每個形狀、高程與屬性、地物數量，以及座標系統的 EPSG 代碼（`.prj` 與 GeoPackage）。我們自己的讀取器讀回的結果也相同。
- GeoJSON 檔案遵循 RFC 7946：經度在前、緯度在後，沒有 `crs` 成員，外環為逆時針、孔洞為順時針；位置與 PROJ 的結果吻合至 2 mm。
- 已匯出一個地面座標專案，並將每個點與其格網座標逐一核對。
- 這些檔案尚未在其他 GIS 程式中開啟測試。首次交付前，請先與對方的 GIS 部門確認，再行依賴。
