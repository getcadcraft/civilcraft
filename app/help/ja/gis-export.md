多くの市や郡は、プロジェクトの完了時に出来形データをGIS形式で求めます。管路と構造物の位置、最終的な勾配、道路の中心線などです。**GIS › 書き出し** は、CivilCraft が保持している内容を、種類ごとに1つのGISレイヤーとして書き出します。

## 書き出し前に

1. {{ui:座標}} でプロジェクトの座標系を設定します。GIS部門は数値がどこにあるかを知る必要があります。座標系がないと、ファイルにはプロジェクト独自の数値が含まれ、その数値の名前が示されません。
2. 地表面、線形、造成面、管路網を、納品する状態になるよう確認します。
3. 部門に、必要な形式と座標系を確認します。多くの部門は、州平面座標系のゾーンのシェープファイルを求めますが、新しいシステムではGeoPackageを使用します。

## 書き出し

1. **GIS** グループの {{ui:書き出し}} をクリックします。
2. **内容** で、送信する種類にチェックを付けます。各項目にはフィーチャーの数が表示されます。まだ何もない種類はグレーで表示されます。
3. **形式** で、形式を選択します。
4. 座標と単位に関する注意を読み、ダウンロードボタンをクリックします。ステータス行に、書き出した内容と、短縮されたフィールド名が表示されます。

ダイアログには、標高グリッドの書き出し（{{ui:GeoTIFF標高グリッドとしての地表面}}）も含まれます。詳細は [標高グリッドとLiDAR](topic:elevation-grids-and-lidar) を参照してください。

## 各種類の内容

| 種類 | 形状 | フィールド |
|---|---|---|
| 測量点 | 標高を持つ点 | `P` 点番号、`N` 北距、`E` 東距、`Z` 標高、`D` 説明 |
| 既存地盤と造成後地表面の等高線 | 各標高の線 | `ELEV` |
| 地性線 | 標高を持つ線 | `NAME` |
| 地表面の境界 | ポリゴン（描かれた境界、なければ地表面の端） | `NAME` |
| 線形 | 中心線 | `NAME`、`LENGTH`、`STA_START`、`STA_END`（測点は数値のみ） |
| 造成面 | 造成面の標高にあるポリゴン | `NAME`、`ELEV`、`AREA` |
| 法尻線 | 標高を持つ線（造成面とコリドー） | `NAME` |
| コリドーのフィーチャーライン | 標高を持つ線：中心、舗装端、路肩 | `NAME`、`CODE`（CL、EOP_L、EOP_R、SH_L、SH_R） |
| 管路 | 上側の管底から下側の管底までの線 | `NAME`、`FROM`、`TO`、`DIA`、`DIA_UNIT`、`INV_UP`、`INV_DN`、`SLOPE`（パーセント）、`LENGTH`、`NETWORK` |
| 構造物 | 天端の点 | `NAME`、`RIM`、`INVERT`（そこにある管の最も低い管底）、`SUMP`、`DIA`、`DIA_UNIT` |
| 各GISレイヤー | 取り込んだままの状態 | 独自のフィールド |

長さ、測点、標高は、プロジェクトの単位（米国測量フィートまたはメートル）で表されます。管と構造物の径は、フィートのプロジェクトではインチ、メートルのプロジェクトではミリメートルです。`DIA_UNIT` でどちらかがわかります。

## 形式

- **シェープファイル**: 種類ごとのシェープファイル（`.shp`、`.shx`、`.dbf`）、テキストがUTF-8であることを示す `.cpg`、座標系を示す `.prj` を含む1つの `.zip`。標高を持つ形状は、シェープファイルのZ型で書き出されます。形式の要件により、10文字を超えるフィールド名は短縮され、ステータス行に一覧が表示されます。
- **GeoPackage**: 種類ごとにテーブルを持つ1つの `.gpkg` ファイル。座標系はEPSGコードとともに保存されます。ファイルは1つにまとまり、長いフィールド名も保持されます。
- **KML** または **KMZ**（KMLを圧縮したもの）: Google Earth や Web 地図用の、緯度と経度の1ファイル。種類ごとのフォルダーがあり、各フィーチャーは NAME フィールドから名付けられたプレースマークで、すべてのフィールドが拡張データとして含まれます。高さはメートル単位（高度モードは絶対）。GeoJSON と同様に、プロジェクトの座標系が必要です。
- **GeoJSON**: 緯度と経度の1ファイル（GeoJSON標準では他の形式は許されません）。各フィーチャーには `kind` プロパティ（`pipes`、`structures` など）があり、受け取り側で分割できます。高さは標準の要求どおりメートルに変換されますが、プロジェクトの鉛直基準のままです（CivilCraft はジオイドモデルを持ちません）。座標系のないプロジェクトはGeoJSONを書き出せず、ダイアログにその理由が表示されます。

## グリッドであり地表ではない

GIS部門は、データを座標系の**グリッド**座標で保持しています。プロジェクトが地表座標またはローカル座標を使用している場合（{{ui:座標}} で設定）、書き出し時にすべての座標がグリッドに戻されます。そのため、ファイルの数値は平面図の数値と、スケール係数（ローカル系では回転も）の分だけ異なります。点フィールドの `N` と `E` にもグリッド値が入ります。ダイアログにもその旨が表示されます。

:::tip
ファイルと一緒に短い説明を送ってください。座標系とそのEPSGコード、標高の鉛直基準、単位、各ファイルの内容を記載します。
:::

## 検証内容

- 書き込まれた各ファイルは、多くのGISプログラムが読み込みに使うライブラリであるGDALで読み直して確認しました。各形状、標高、属性、フィーチャー数、座標系（`.prj` と GeoPackage では EPSG コード）が確認されています。当社の読み取り機能でも同様に読み直せました。
- GeoJSON ファイルは RFC 7946 に従います。経度が緯度より先、`crs` メンバーなし、外周リングは反時計回り、穴は時計回りです。位置はPROJと2 mm以内で一致しました。
- 地表座標のプロジェクトを書き出し、すべての点をグリッド座標と照合しました。
- ここの内容は、まだ他のGISプログラムで開いて確認していません。頼る前に、最初の納品物を部門と確認してください。
