市や郡のGIS部門は、敷地の情報をGISファイルで提供します。区画、地役権、等高線、公共設備、測量の基準点などです。CivilCraft は、そのうち3種類のファイルを、平面図上で設計の下に置かれる **GISレイヤー** として開きます。

| ファイル | 開くもの |
|---|---|
| シェープファイル | `.shp` と、一緒にある `.shx`、`.dbf`、`.prj`、`.cpg`（すべて選択）、または受け取った `.zip`。複数のシェープファイルを含む zip は、複数のレイヤーになります。 |
| GeoJSON | `.geojson` ファイル（最初の行に `FeatureCollection` または `Feature` と書かれた `.json` ファイルも可）。 |
| GeoPackage | `.gpkg` ファイル。含まれるすべてのフィーチャーテーブルが一覧表示されます。 |
| KML または KMZ | `.kml` ファイル（Google Earth や Web 地図から）、または圧縮された `.kmz`。各フォルダーがレイヤーになります（点、線、ポリゴンが混在する場合はそれぞれに分割されます）。プレースマークの名前、説明、拡張データは属性になります。高さはメートル、緯度と経度は GeoJSON と同様です。 |

点、マルチポイント、線、穴のあるポリゴン、複数の部分からなる形状は、ファイルに含まれていれば標高（z）とともに読み込まれます。計測値（M）は除外されます。標高グリッドとLiDARも同様に開きます。[標高グリッドとLiDAR](topic:elevation-grids-and-lidar) を参照してください。

## ファイルを開く

1. **GIS** グループの {{ui:インポート}}（または {{ui:開く}}）をクリックし、ファイルを選択するか、平面図にドロップします。ファイルはこのコンピューター上で読み込まれ、アップロードされることはありません。
2. **GISデータのインポート** ダイアログに、見つかったすべてのレイヤーが表示されます。種類、フィーチャーの数（ジオメトリがないものの数を含む）、属性フィールドの数、ファイルが示す座標系が表示されます。不要なレイヤーのチェックを外します。
3. 下記の **座標系** の項目と **実行内容** の行を確認し、{{ui:インポート}} をクリックします。
4. レイヤーは平面図と、左のパネルの **GISレイヤー** の下に表示されます。インポートは1回の操作です。{{key:Mod+Z}} で取り消せます。

大きなファイルでは、平面図の上に進行状況が表示され、{{ui:キャンセル}} ボタンが表示されます。

## 座標系

GISファイルは座標系によって位置を示します（シェープファイルの `.prj`、GeoPackage の空間参照テーブル。GeoJSON は常に緯度と経度）。CivilCraft は各レイヤーを、そのファイル自身の座標系からプロジェクトの座標系へ変換します。推測は行いません。

- **プロジェクトに座標系がある場合**（{{ui:座標}} で設定）: 独自の座標系を持つすべてのレイヤーが、地表またはローカルの調整を含めて、プロジェクトの座標系に変換されます。`.prj` のないファイルには2つの選択肢があります。**プロジェクトと同じ**（数値はそのまま読み込まれます）または **ファイルの座標系を指定**。
- **プロジェクトに座標系がなく、ファイルがプロジェクトの単位の投影座標系である場合**（例：フィートのプロジェクトに対する米国測量フィートの州平面座標系）: ダイアログは **そのファイルの座標系をプロジェクトの座標系として使用** を提示します。これはインポートと同じ1回の操作で設定されます。プロジェクト内の何も移動しません。座標系は数値の意味を示すだけです。代わりに別の座標系をプロジェクトに選ぶこともでき、その場合レイヤーはその座標系へ変換されます。
- **プロジェクトに座標系がなく、ファイルが緯度と経度（すべての GeoJSON）または別の単位である場合**: 座標系を選択するまで {{ui:インポート}} はグレーのままです。ピッカーはデータの近くから始まります。
- **プロジェクトもファイルも座標系を示していない場合**: 数値はそのまま読み込まれ、ダイアログにその旨が表示されます。

標高も変換されます。GeoJSON の高さはメートルです（GeoJSON標準の定め）。その他のファイルの高さは、そのファイル自身の座標系の単位として扱われます。

:::warning
GeoJSON ファイル内の位置が経度 ±180°、緯度 ±90° の範囲外の場合、それは緯度と経度ではありません。そのフィーチャーは除外され、ダイアログに件数が表示されます。このようなファイルは通常、座標系を保存せずに投影座標で保存されたものです。再度入手するか、`.prj` のあるシェープファイルを依頼してください。
:::

NAD83 は、GeoJSON が使用する WGS 84 と同じものとして扱われます。北米では両者は数メートル異なるため、GeoJSON データはその程度ずれることがあります。最適なずれの補正に格子ファイル（例：NAD27 の NADCON）が必要な場合、CivilCraft は簡易的な公開のずれを使用し、座標系ダイアログにその精度（NAD27 では約20 m）が表示されます。格子を追加するまでの間です。詳細は [格子シフトファイル](topic:coordinate-systems) を参照してください。

## GISレイヤー

**GISレイヤー** の各行には以下があります。

- レイヤーの表示と非表示を切り替えるチェックボックス（非表示のレイヤーは選択もされません）。
- 一覧から選んだ色。
- メニュー（三つの点）。{{ui:ここにズーム}}、{{ui:地表面に使用…}}、{{ui:名前の変更…}}、{{ui:削除}} があります。

表示、非表示、色の変更、名前の変更、削除は、いずれも元に戻す操作の対象です。GISレイヤーはプロジェクトファイルに保存され、ファイルを開くと戻ります。また、平面図のPDF印刷、DXF および DWG の書き出しにも含まれ、それぞれ `GIS-` と番号の付いたレイヤーに配置されます。

## 属性からフィーチャーにラベルを付ける

レイヤーの {{ui:その他}} メニュー（**GISレイヤー** の三つの点）で、**ラベル** の下のフィールドを選ぶと、各フィーチャーの値がレイヤーの色で平面図に表示されます。点はその横に、線は最も長い部分の中央に（左から右へ読めるように向きを変えて）、ポリゴンは中心に表示されます。数値は小数点以下3桁まで表示されます。ラベルは縮尺にかかわらず、用紙上で高さ 1.8 mm となり、PDF印刷、DXF、DWG に含まれます。ラベルを取り除くには **ラベルなし** を選択します。各変更は1回の操作（{{key:Mod+Z}} で元に戻せます）です。1つのレイヤーには最大 5,000 個のフィーチャーにラベルが付きます。

## フィーチャーを確認する

{{ui:選択}} をオンにしてフィーチャーをクリックします。**プロパティ** には、そのレイヤー、どのフィーチャーか、形状（部分、穴、頂点）、標高、取り込み元のファイル、そのファイルの座標系、そして全属性が表形式で表示されます。属性は読み取り専用です。CivilCraft はGISデータを取り込んだままの状態で表示し、編集はしません。

ポインターの下に線と点の両方があるときは点が優先されます。ポリゴンの内側では、最も小さいポリゴンが選ばれます。

## 地表面に使用

レイヤーのメニューを開き、{{ui:地表面に使用…}}（または **プロパティ** のボタン）を選択します。提供される内容はレイヤーによって異なります。

| レイヤー | 変換先 |
|---|---|
| 標高を持つ線（3D線） | それぞれの標高での地性線 |
| 標高を持たないが数値フィールドのある線（等高線） | 選択したフィールドの標高での地性線 |
| ポリゴン | 地表面の境界（選択したポリゴン、なければ最大のもの）、または辺に沿った地性線 |
| 標高を持つ点、または標高フィールドのある点 | 測量点。レイヤー名で説明され、点グループを形成します |

各使用は1回の元に戻す操作で、形状をプロジェクトにコピーします。レイヤー自体はそのまま残ります。標高はプロジェクトの単位で取り込まれます。

## 緯度と経度を含む点ファイル

ヘッダーに **緯度** と **経度** の列（`lat`、`latitude`、`lon`、`long`、`longitude`）がある点ファイルは、北距と東距ではなく度として読み込まれます。インポートダイアログにもその旨が表示されます。{{ui:インポート}} を押すと、点はプロジェクトの座標系に変換されます。座標系のないプロジェクトでは、先に選択するよう求められます。度がフィートとして読み込まれることはありません。緯度 ±90° または経度 ±180° の範囲外の行は、理由とともに拒否されます。標高の列はそのまま、プロジェクトの単位で取り込まれます。

## 座標系を含むLandXMLファイル

開いたLandXMLファイルに `CoordinateSystem` 要素（EPSGコード、WKT の記述、または座標系名）がある場合、CivilCraft はそれをプロジェクトの座標系として提示します。受け入れても何も移動せず、数値の意味だけが示されます。

## 検証内容

- 各読み取り機能は、GDAL（多くのGISプログラムが使用するライブラリ）で書かれたファイルと照合しました。対象は、標高の有無を含むあらゆる種類のシェープファイル、複数の部分からなる線、穴のあるポリゴン、空のジオメトリ、テキスト、数値、日付、真偽値の属性、`.cpg` ありとなしの UTF-8 および Windows-1252 のテキスト、複数のシェープファイルを含む zip、すべてのジオメトリ型の GeoJSON、4テーブルの GeoPackage です。すべてのジオメトリ、標高、属性が一致しました。
- 緯度と経度、およびUTMから変換した位置は、PROJ（GDAL の背後にある投影ライブラリ）と 3 mm 以内で一致しました。
- 破損したファイル（途中で切れている、サイズが偽られている、zip が壊れている、GeoPackage が壊れている）は、わかりやすい1つのメッセージを表示し、処理が止まることはありません。
- ここの内容は、まだ他のGISプログラムで開いて確認していません。ファイルジオデータベース、KML、KMZ は、まだ読み込めません（[未対応の機能](topic:not-built-yet) を参照）。
